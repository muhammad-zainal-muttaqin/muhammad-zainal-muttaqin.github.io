Research · 2026Universitas Lambung MangkuratPaper: IEEE ICIC 2026, 1st author

Counting bunches per tree, not per photo

Problem
Each tree is photographed from 4 or 8 sides, so one bunch shows up in several photos. Adding up the detections overcounts by about 1.8×.
What I did
Compared 29 hand-written de-duplication rules with SVM and random-forest counters on 953 trees from two plantations, keeping the detector fixed. Wrote audits that caught inconsistent cross-view links in the ground truth and fixed 48 trees.
Result
Given correct detections, the counter is right within ±1 bunch per grade for 96.1% of trees. With real YOLO detections it drops to 71.6%, and all 15 detector × counter pairs land between 64% and 72%. The detector is the bottleneck, not the counting.

Sawit Vision API

Problem
A research checkpoint is not something a farm app or another team can call.
What I did
Wrapped the detector I trained in a FastAPI service. Exported it to ONNX and rewrote letterboxing and NMS in NumPy, so it runs without PyTorch. Every request is logged to SQLite, tests run on real field photos in CI, and it ships as a Docker image.
Result
37 ms per photo on an M1 with CoreML. On 568 new field photos the YOLO26n model put 2 boxes on ground or trunk, where the older YOLOv8n put 216.

PalmAnnotate, the tool the dataset was built with

Problem
Multi-view labels need more than boxes: annotators have to say which box on side 2 is the same bunch as a box on side 3.
What I did
Built an offline browser app to fix YOLO boxes, link the same bunch across neighbouring sides and export one JSON file per tree. Then rebuilt it as a native Android app for field work: camera capture, an Orbbec depth camera over USB, GPS, and on-device detection with ONNX Runtime.
Result
Used to build the SawitMVC dataset. The Android app is built by CI and released as an APK (v0.3.77, October 2026).

Research · 2026

Does a depth camera help?

Trained YOLO26l, RT-DETR-L and RF-DETR-L on RGB and on 4-channel RGB+depth, across about 80 logged experiments. Depth helped find bunches but not grade them, and I traced a misleading comparison to an 80-day gap between two capture campaigns.

A fair detector benchmark

A fixed protocol on 3,992 images and 17,987 boxes: dataset audit, resolution sweep, learning curve, 11 architectures × 2 seeds, one-stage vs two-stage. Then 153+ automated tuning runs to see how far the ceiling moves.
