Sawit Vision API

  • mAP@50 0.771 (val), 5 classes
  • 23 ms / image with ONNX + CoreML vs 88 ms PyTorch CPU
  • /detect, /history, /stats endpoints
Problem & what I built

Problem Plantation staff need a bunch count per ripeness class from a tree photo, through an API other apps can call.

What I built Exported my YOLOv8n ripeness detector to ONNX, wrote letterbox pre-processing and class-aware NMS in NumPy (no PyTorch at runtime), served it with FastAPI, logged every request to SQLite, added a web demo, 6 pytest tests and a Dockerfile.

  • YOLOv8
  • ONNX Runtime
  • FastAPI
  • SQLite
  • Docker
  • pytest

Research, ULM · first-author paper (IEEE ICIC 2026)

Multi-view oil palm bunch counting

  • Macro accuracy ±1 bunch: 96.1% with ground-truth features
  • 87.6% with the best heuristic
  • 71.6% fully end-to-end from detector output
Problem & what I built

Problem Each palm tree is photographed from 4–8 sides, so the same bunch appears several times and naive counting over-counts.

What I built Benchmarked de-duplication methods (heuristics, SVM on cross-view features, end-to-end detector → SVM) on 953 trees from two plantations under one fixed detector.

  • Python
  • YOLO
  • scikit-learn
  • pandas

Research, ULM

RGB vs RGB+Depth detector study

  • 3 architectures × 2 modalities
  • Found and documented temporal domain shift between collection batches
  • Experiment map site for the whole study
Problem & what I built

Problem Does adding a depth channel help detect and grade fruit bunches, and which modern detector is best for it?

What I built Compared YOLO26l, RT-DETR-L and RF-DETR-L on RGB and 4-channel RGB+D data, then a modular two-stage pipeline (class-agnostic localisation + ripeness classifier); 80+ tracked experiments with a chronological log and final report.

  • PyTorch
  • Ultralytics
  • RT-DETR
  • RF-DETR
  • Kaggle GPU
